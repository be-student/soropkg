# Getting Started

This guide walks you through installing soropkg, inspecting a live contract, and setting up drift monitoring.

---

## Requirements

- **Node.js** 18 or higher
- **npm** 8 or higher
- A deployed contract address to inspect (or a project to monitor)

---

## Installation

Install the CLI globally via npm:

```bash
npm install -g soropkg
```

Verify the installation:

```bash
soropkg --version
```

---

## Inspect a live contract

Point soropkg at any deployed contract to read its interface straight from the chain:

```bash
soropkg inspect CAQQR5SWBXKIGZKPBZDH3KM5GQ5GUTPKB7JAFCINLZBC5WXPJKRG3IM7
```

Use `--json` for machine-readable output, or `-n testnet` to query another network.

## Monitor your dependencies for drift

<Steps>

### Scaffold a watchlist

```bash
soropkg check --init
```

This writes a `soroban-watch.toml`. Edit it to list the contracts your app depends on:

```toml
network = "mainnet"

[[contracts]]
name = "soroswap-router"
id   = "CAG5LRYQ5JVEUI5TEID72EYOVX44TTUJT5BQR2J6J77FH65PCCFAJDDH"
```

### Record a baseline

```bash
soropkg check
```

The first run records each contract's current interface into `.soroban/snapshots.json`.

### Detect breaking upgrades

Run `soropkg check` again — in CI, or after a dependency ships an upgrade. It diffs each live interface against its baseline and exits non-zero on any breaking change, so a dependency's upgrade fails your build instead of your users. Commit both `soroban-watch.toml` and `.soroban/snapshots.json` to your repo.

</Steps>

## Networks

soropkg supports all three Stellar networks via `-n, --network`:

| Network | Value | Description |
|---|---|---|
| `mainnet` | default | Production |
| `testnet` | `-n testnet` | Public test network |
| `futurenet` | `-n futurenet` | Experimental pre-release network |

```bash
soropkg inspect -n testnet CABC123...
```

Provide your own endpoint with `--rpc <url>` if the default public RPC is rate-limited.
