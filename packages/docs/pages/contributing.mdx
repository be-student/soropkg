# Contributing

soropkg is open source and welcomes contributions of all kinds — bug reports, documentation improvements, new features, and test fixtures.

---

## Repository structure

```
soropkg/
├── packages/
│   ├── core/        # @soropkg/core — shared TypeScript types
│   ├── cli/         # CLI entry point, commands, and the spec engine
│   ├── website/     # Marketing landing page (Next.js)
│   └── docs/        # This documentation site (Nextra)
├── seeds/           # Curated mainnet contract reference data
└── package.json     # Root workspace
```

---

## Getting started

<Steps>

### Clone the repository

```bash
git clone https://github.com/soropkg/soropkg.git
cd soropkg
```

### Install dependencies

```bash
npm install
```

### Build all packages

```bash
npm run build
```

### Run the CLI locally

```bash
node packages/cli/dist/index.js --help
```

</Steps>

---

## Adding contract reference data

A quick first contribution is adding a Soroban contract to the reference/fixture data.

1. Find the deployed contract address(es) on [StellarExpert](https://stellar.expert)
2. Add an entry in `seeds/contracts.ts` following the existing format
3. Run `soropkg inspect <address>` to verify the interface parses correctly
4. Open a pull request with a description of the protocol

---

## Reporting bugs

Open an issue on [GitHub](https://github.com/soropkg/soropkg/issues) with:

- soropkg version (`soropkg --version`)
- The command you ran
- The full error output
- Expected vs actual behaviour

---

## Submitting changes

<Steps>

### Fork and branch

```bash
git checkout -b feat/my-feature
```

### Make your changes and commit

Follow the existing commit message style — short imperative subject line, no co-authors.

### Open a pull request

Describe what you changed and why. Link any relevant issues.

</Steps>

---

<Callout>
  For large features or architectural changes, open an issue first to discuss the approach before investing time in an implementation.
</Callout>
